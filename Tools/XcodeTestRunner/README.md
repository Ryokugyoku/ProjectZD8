# XcodeTestRunner(xcodebuild の直列・時間上限つき実行)

ローカルの `xcodebuild test` を、同じマシンで同時に1本だけ、時間上限つきで走らせるためのラッパー。この文書が仕様の正。

- 実行環境: Python 3.9 以上、標準ライブラリのみ。macOS で使う。
- 置き場所: `Tools/XcodeTestRunner/`(パッケージ `xcode_test_runner/`、入口 `run_xcodebuild.py`、テスト `Tests/`)。
- 製品コードに依存しない。渡されたコマンドの中身は解釈しない(`xcodebuild` 以外でも動く)。

## 1. 解決する問題

| 問題 | 対策 |
| --- | --- |
| `xcodebuild test` を複数のセッションから同時に走らせると、テストホストが落ちて終了しなくなる | 同じユーザーの全セッションで共有するロックを取り、1本ずつ実行する(§3) |
| 実装を壊すと「失敗」ではなく「止まらない」になるテストがあり、メモリを使い切る | 時間上限を過ぎたら、コマンドとテストホストを止める(§4) |
| 強制終了されたラッパーのロックが残り、次の実行が待ち続ける | 持ち主のプロセスがいないロックは回収する(§3) |

## 2. コマンド

```sh
python3 Tools/XcodeTestRunner/run_xcodebuild.py --limit SECONDS [--lock-wait SECONDS] [--kill-pattern REGEX]... -- COMMAND [ARG...]
```

- `--limit SECONDS`(必須): コマンドの実行時間の上限。1 以上の整数。
- `--lock-wait SECONDS`(省略時 3600): ロックを待つ時間の上限。0 以上の整数。0 は「待たない」。
- `--kill-pattern REGEX`(0回以上): 時間上限で止める時に、コマンド行がこの正規表現に一致するプロセスも止める(§4)。
- `--` の後ろがそのまま実行するコマンド。シェルは通さない。
- コマンドの標準出力・標準エラーはそのまま流す。本ツール自身のメッセージは標準エラーへ出す。
- 引数が不正な場合(`--limit` がない、整数でない、範囲外、`--kill-pattern` が正規表現として不正、`--` の後ろが空)は、理由を標準エラーに出して終了コード 2。コマンドは実行しない。

## 3. ロック

- 場所: 環境変数 `XCODE_TEST_RUNNER_LOCK_DIR` があればそのパス(空文字列は未設定として扱う)。なければ `<ホーム>/Library/Caches/ProjectZD8/xcodebuild.lock`。`<ホーム>` は環境変数 `HOME`、無い・空ならユーザー情報のホームディレクトリ。親ディレクトリがなければ作る。
  - 誰でも書き込める場所(`/tmp`、`/private/tmp`、`/var/tmp`)を既定にしない。他のユーザーが先に同じ名前のディレクトリやリンクを置けるため。ユーザー専用のキャッシュ置き場は本人しか書けない。
  - 以前の bash スクリプト(`xcb.sh`、ロックは `/private/tmp/claude-<uid>/projectzd8-xcodebuild.lock`)とはロックを共有しない。併用すると同時実行を防げないので、切り替え後は本ツールだけを使う。
- 形: ディレクトリ。中のファイル `pid` に、持ち主(本ツール)のプロセス ID を10進数で書く。ディレクトリの作成(`mkdir`)が成功した側が持ち主になる。
- 取れない時: `XCODE_TEST_RUNNER_POLL_SECONDS` 秒(省略時 5。小数可)ごとに取り直す。`--lock-wait` を過ぎたら `LOCK_TIMEOUT` で始まる行を標準エラーに出して終了コード 125。コマンドは実行しない。
- 残ったロックの回収: 次のどちらかなら、持ち主がいないとみなしてディレクトリを消し、すぐ取り直す。
  - `pid` の番号のプロセスが存在しない。
  - `pid` が無い・空・数字でない状態で、ディレクトリの更新時刻から `XCODE_TEST_RUNNER_STALE_SECONDS` 秒(省略時 30。小数可)以上たっている。
- 解放: 正常終了、時間上限、例外、`SIGINT` / `SIGTERM` を受けた時のいずれでも、自分が取ったロックを消してから終わる。他のプロセスが持つロックは消さない。

## 4. 時間上限

- コマンドは新しいプロセスグループ(セッション)で起動する。
- `--limit` 秒以内に終われば、コマンドの終了コードをそのまま返す(シグナルで終わった場合は 128 + シグナル番号)。
- 過ぎた場合:
  1. `TIMEOUT` で始まる行(上限の秒数を含む)を標準エラーに出す。
  2. プロセスグループへ `SIGTERM` を送る。
  3. `XCODE_TEST_RUNNER_GRACE_SECONDS` 秒(省略時 5。小数可)待ち、残っていれば `SIGKILL` を送る。
  4. `--kill-pattern` があれば、コマンド行(`ps -axo pid=,command=` の command)が正規表現に一致(`re.search`)するプロセスへ `SIGTERM` を送り、同じ秒数だけ待って、残っていれば `SIGKILL` を送る。**本ツール自身とその祖先のプロセスは対象から外す**(本ツールのコマンド行には正規表現そのものが入っていて一致するため)。
  5. ロックを解放し、終了コード 124 を返す。
- 本ツールが `SIGINT` / `SIGTERM` を受けた時は、上の 2〜4 と同じ手順でコマンドを止め、ロックを解放し、128 + シグナル番号を返す。

## 5. 終了コード

| コード | 意味 |
| --- | --- |
| コマンドの終了コード | 上限内に終わった |
| 2 | 引数が不正 |
| 124 | 時間上限で止めた |
| 125 | ロックを待つ時間の上限を過ぎた |
| 128 + N | シグナル N で終わった(コマンド、または本ツール) |

コマンドが見つからない・実行できない場合は、理由を標準エラーに出して終了コード 127。

- §3・§4 の環境変数の値が不正な場合(数字でない、`POLL` が 0 以下、`STALE`・`GRACE` が負)は、引数の不正と同じく終了コード 2。空文字列は未設定として扱う。
- 想定外のエラー(ロックの親ディレクトリを作れない等)は、理由を標準エラーに出し、ロックを解放して終了コード 1。

## 5.1 既知の制限

- 2本が同時に同じ残ったロックを回収すると、片方が、もう片方の取り直した直後のロックを消すことがある(消す直前に `pid` を読み直して起きにくくしているが、完全には防げない)。
- 持ち主が終了した後に同じ PID が別のプロセスへ再利用されると、そのロックは使用中とみなされる。この場合は `--lock-wait` を過ぎて 125 になるので、ロックのディレクトリを手で消す。
- コマンドが上限内に終わった時は、同じプロセスグループに残った子孫を止めない。

## 6. 実装上の制約

- 共通ルール §5 に従う(1関数の循環的複雑度10・認知的複雑度15・ネスト3段・80行、1ファイルの関数20個・500行、1行160文字)。責務ごとにモジュールを分ける(例: 引数、ロック、実行と停止、プロセス一覧、CLI)。
- 日本語の docstring を付け、関数には `責務:` の一文を書く。
- 待ちとポーリングには必ず上限を付ける。`pgrep` / `pkill` は使わない。
- テストは実際の `xcodebuild` を呼ばない。`sys.executable -c ...` などの短いコマンドと、上の環境変数で短くした待ち時間を使い、どのテストも数秒で終わるようにする。
